## 三、坑清单（阶段1文档必录）

1. **`input text` 弃用**：中文抛 NPE(code=255)；ASCII 走拼音组词层不上屏（荣耀版百度输入法），截图证据 `img/_v2e_search.png`
2. **零位移 swipe ≠ 长按**：被识别为点击进了文件夹；长按必须 motionevent DOWN/UP
3. **OCR 标签三坑**：相邻图标标签合并（"应用市场文件管理"）；误字（搜索→搜素、浏览器→刘览器）；逐次结果有波动（同一屏"笔记"时有时无）→ 容错匹配 + 标签仅当锚点
4. **荣耀桌面标签不可点**：点击标签无响应，必须锚定到图标中心（label→icon 上移偏移）
5. **uiautomator dump 限制**：桌面(动画)idle 失败；微信反无障碍仅 3 节点；IME 开启时搜索框文本可能不入 dump
6. **findMultiColors 渐变色差**：壁纸上 12px 内色差超 threshold 会假阴性（探针矩阵定位为数据问题非 API 问题）
7. **am start 只前置 task 不回主页**：复位用 `am force-stop` + 重启（顺带验证 shell 可 force-stop）
8. **坐标体系**：截图/dump 均为原生 1264x2736，PC 端看缩放图需 1.374 换算（1264/920）
9. Git Bash 下 adb 路径转换：`/sdcard/...` 需写 `//sdcard/...` 或整体引号

## 六、wxauto-B 试点实证（1031 晚, 全链路真实运行）

**结论: B 模式规范在真实业务端到端成立**。微信单聊自动回复全链（启动→dumpsys 前台→OCR 判主界面→搜索→讯飞条粘贴中文→联系人 sim=1.00→聊天页→像素带扫描→长按弹框复制→组装→粘贴→发送→验证）22 次 OCR 全部 paddle small（2.7~4.6s/次），全程零无障碍零 MediaProjection。

新增实证与教训:
1. **剪贴板读回绕行验证通过**: 微信前台时后台 getClip 读不到 → "AutoJs6 置前→getClip→am start 回切(前置已有 task 自动恢复聊天页)" 取原文完整成功; am start 的 "task brought to front" warning 属预期行为
2. **paddle 插件 stopped 顽疾再次复现**: 插件进程被系统杀 → "未找到可用的 Paddle OCR 插件" → mlkit 兜底链路真实生效(1.5s/38条); 修复 = 唤醒+启用位(`_fix_small_only.js`: medium 停用/small 启用, 冒烟 3652ms); 注意通用修复脚本会把 medium 启用位也写回 true, 与"仅 small"冲突
3. **发送验证须取最底部匹配气泡**: 历史回复含同文本, 首项匹配会抓到老气泡(教训: 日志曾报 "「31」" 实为新发 "「1」")
4. **配置安全阀必须人工复核**: REPLY_DRY_RUN 笔误导致意外实发一条(内容恰为正常回复 "「1」消息已收到", 撤回超时); 已修复并固化 DRY_RUN=true 安全阀
5. **试点后环境**: enabled_accessibility_services=null (整机零无障碍注册) — B 模式最强隐蔽姿态
6. 非受限通道澄清: app.launch/setClip/getClip/通知监听/storage 属应用自身权限(零无障碍), B 模式允许
